# Wave Anatomy — the shape of a sine, taught by moving its parameters

`y = A · sin( B · (x − C) ) + D`, one beat per parameter, in about thirty seconds.

The point of the example is that **no wave is drawn anywhere**. `resources/diagram/plot.svg`
carries a grid, two axes and a scale — furniture. Every curve in all four beats is
generated by an `annotation` from its own equation, sampled by the compiler. The
authored line

```yaml
expression: sin(radians(x))
domain:
    from: 0
    to: 360
```

is not a label for the curve. It is what produced every point of it. Beat 1 ends by
putting that line on screen beside the curve it made, because in every other example the
document *describes* a picture and here it *is* the mathematics.

The plot window is exactly **one cycle**, so "one cycle" in the narration is the whole
plot and a frequency of three shows three. Nothing has to be counted twice.

## The four beats

| Beat | Scene | What moves | The lesson |
| ---- | ----- | ---------- | ---------- |
| 1 | `scene_01_wave.yaml` | The curve draws itself, a dot walks it, the source line arrives | The vocabulary — cycle, crossing, peak — and where the curve came from |
| 2 | `scene_02_amplitude.yaml` | **A** steps 0.5 → 1 → 2 | Peaks climb; **the crossings never move** |
| 3 | `scene_03_frequency.yaml` | **B** steps 1 → 2 → 3 | Cycles multiply; **the height never changes** |
| 4 | `scene_04_shift.yaml` | **C** and **D** glide | Both are translation — and a sine shifted 90° **is** a cosine |

Beats 2 and 3 are deliberate mirrors of one another: same three-step shape, same
ghosting, same ending with every value on screen at once. Only the function and the
tag text differ. Read side by side, the symmetry is the argument — amplitude changes
height and holds position, frequency changes position and holds height.

`scene_00_tts_generation.yaml` is synthesis-only; it generates the narration under
`audio/` from the scripts under `script/`. `scene_stitch.yaml` concatenates the four
clips into the headline deliverable, mixing each beat's line onto its own clip.

## Two layers, two audiences

**The narration is trigonometry and nothing else.** Not one spoken line mentions
Kinaigraph, a function, or a capability. The engine's story is carried entirely by the
capability legend in the bottom-left corner — one small box per beat, naming in
Kinaigraph's own vocabulary what is being done:

| Beat | Legend |
| ---- | ------ |
| 1 | **Function drawing** — a function, sampled into a curve |
| 2 | **Constants in the function** — a number becomes geometry |
| 3 | **Opacity** — earlier curves held on to compare |
| 4 | **Move** — generated geometry translates |

The four legends are not four *exclusive* capabilities — beats 2 and 3 lean on the same
mechanism, and every beat is function drawing underneath. Each legend names something
true of its own beat, chosen so the four together cover more of the language than
repeating one would. A legend names the capability the beat is a good place to notice,
not the only one it uses.

Each names a **property or an action**, never the action that merely carries a property:
beat 3 is `opacity`, not "show and opacity", because a viewer sees the property and the
action adds a word that buys nothing.

A viewer here to learn about waves follows the voice and never has to care what rendered
them. A reader evaluating the language can read the four boxes and ignore the voice
entirely, and still get the whole account. Neither audience is interrupted for the
other's benefit, which is what makes it worth spending the screen space.

The legend is deliberately **off the plot's palette** — desaturated warm grey against a
cool diagram — because it is commentary about the video rather than part of it. Beat 1's
larger green source box is the same idea at full volume: the legend *names* function
drawing, and the box *shows* the line that did it.

**On the two words.** `expression` is a Kinaigraph FIELD name, and in mathematics it means
something narrower than `function` — a formula, not the thing it defines. Since this piece
teaches mathematics, prose says **function** throughout and `expression` appears only where
YAML is quoted verbatim, as in beat 1's source box. The two are not synonyms and nothing is
served by letting them read as though they were.

## How the capabilities show up

- **Generated geometry from a function.** `annotation.curve.function` takes a function of
  `x` — in its `expression` field — a domain, and a scale; the compiler samples and
  flattens it. Change a coefficient and the drawing changes on the next render, because
  there is no drawing to fall out of step with it.
- **Trigonometry in a function, with the unit boundary made explicit.** `sin` operates
  in radians and every authored angle in Kinaigraph is in degrees, so the domain is
  written in degrees and converted at the point of use — `sin(radians(x))`. The
  conversion is visible rather than assumed.
- **The axes crossing as a reference point.** `origin: zero` lands the *function's* own
  crossing on the surface's crossing. It is the one reference point no bounding-box cell
  could name, and for a plot it is the only correct one.
- **Riding generated geometry.** The dot in beat 1 travels the curve by name —
  `along: wave`. There is no second copy of the wave for it to
  follow, so it cannot drift off the line it is marking.
- **Drawing as arc length.** `reveal` walks the generated path's own length, so the pen
  moves at the curve's speed rather than fading in place.
- **Narration-driven timing.** Every span in every beat is a fraction of
  `narration.duration`. Re-record a line and the beat re-fits itself; re-render and the
  stitch re-derives its offsets. No duration is measured by hand anywhere in the example.
  ⚠️ The *fractions* are another matter — see below.
- **Theming.** One stylesheet drives three tiers of visual weight — dim grid, warm axes,
  bright curves — so a viewer never has to work out which line is which.

## Two things worth knowing about the build

**Amplitude and frequency step; phase and offset glide.** That is not a stylistic choice.
A phase shift *is* a translation, so a `move` expresses it exactly. A height-only or
width-only stretch has no spelling — the animatable `scale` is a single uniform factor,
and using it would compress the wave horizontally while stretching it vertically, which
is a different lesson. Three declarations at three values are exact, and they let the
earlier values stay on screen as ghosts to compare against, which a morph could not do.

**Deriving from the narration is not the same as syncing to it.** Every span here is a
fraction of `narration.duration`, so the beats re-fit any re-recording — but a fraction
only says *how much* of the line a span gets, never *where the words are inside it*. Equal
thirds put the three curves of beats 2 and 3 across the whole clip while the voice said
"one, two, three" inside two seconds: the first curve arrived before its value was named
and the third arrived **1.75 s after**. Beat 4 was worse in kind — equal thirds started the
vertical slide 1.4 s before "Upward is offset", so the two curves separated while the
viewer was being told they coincide.

So the fractions are tuned to where the words actually land, measured with ffmpeg's
`silencedetect` and recorded in each scene's comments. Each beat is shaped like its script:
an opening clause with the plot still empty, a quick count where each value lands as it is
spoken, and a long tail holding the comparison while the closing clause plays. **These
fractions survive re-recording the same words** — the proportions of a spoken sentence are
stable — **but not a rewrite that changes the script's shape.** Change the words and
re-measure. Beat 1 needed no tuning: its pen and its dot already tracked the description,
the dot reaching the trough as "two-seventy" is spoken.

**The window frame is load-bearing.** `resources/diagram/frame_layer.svg` is declared
after the plot surface, so it draws above the curves. It paints the two side margins in
the scene background and carries the y scale. Beat 4 slides a finite curve sideways;
without the frame the curve travels out through the side of the window, across the axis
and the scale labels, and hangs in the margin looking like a mistake. The sine there is
also sampled a quarter cycle *past* the window, so that after the shift it still reaches
the right edge — the beat claims the shifted sine and the cosine agree across the whole
window, and a curve that ran out early would weaken that claim exactly where nobody is
looking.

## Building it

```sh
# 1. Narration. Needs ELEVENLABS_API_KEY; costs credits, so it is its own step.
./kinaigraph scene_00_tts_generation.yaml -outdir .

# 2. The four beats. Each probes its own line's duration and sizes itself to it.
./kinaigraph scene_01_wave.yaml
./kinaigraph scene_02_amplitude.yaml
./kinaigraph scene_03_frequency.yaml
./kinaigraph scene_04_shift.yaml

# 3. The stitch. Requires all four mp4s to exist so their durations can be probed.
./kinaigraph scene_stitch.yaml
```

## The geometry contract

`plot.svg` and the scene files share five numbers, stated in the SVG's header comment and
repeated as consts in each scene. They are the only thing a scene knows about the
surface; nothing is measured from a render.

| Const | Value | Meaning |
| ----- | ----- | ------- |
| `PLOT_X0` / `PLOT_Y0` | `120` / `380` | Where 0° and y = 0 sit on the surface |
| `PLOT_XS` | `1060 / 360` | Pixels per degree |
| `PLOT_YS` | `120` | Pixels per amplitude unit |
| `DOMAIN_TO` | `360` | One cycle — the window is the cycle |

Change one in the SVG and change it in the scenes. `frame_layer.svg`'s mattes abut the
same x values and must move with them.
